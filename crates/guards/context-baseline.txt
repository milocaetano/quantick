# The recorded ceiling, in bytes, for every context file over the threshold —
# the files a Claude Code or Codex session loads before it reads any code. One
# `path ceiling` pair per line; `#` starts a comment.
#
# These are costs, not targets. Every byte here is paid on every turn of every
# session that loads the file, so the only direction an entry should move is
# down. The `!budget` line caps the whole tracked weight — these ceilings plus
# every tracked file too small to need one — so adding weight anywhere means
# taking comparable weight out somewhere else in the same change.
#
# Kept as data rather than a Rust `const` for the reason the size baseline is:
# a raise is then a data diff a reviewer can see, and `--tighten` can rewrite a
# line-oriented file safely.

# What a session's instructions weigh in total: every ceiling above, plus the
# measured bytes of every tracked file too small to need one. Raising it means

#
# The second half is what makes it a cap rather than a bypass. A budget of
# ceilings alone would pay a branch for splitting a large file into pieces that
# each sit under the threshold: the recorded total falls, `--tighten` writes
# the smaller number down as progress, and a session loads exactly as much
# prose as before. The branch that built this guard did that by accident — of
# the 49,281 bytes it took out of three skills, 37,490 landed in sub-threshold
# `references/` siblings. Counting the remainder also removes the cliff the
# first version had: a file crossing the threshold now moves bytes from the
# unrecorded half to the recorded one, rather than adding 10,000 at a stroke.
#
# The cost is a total that drifts with ordinary edits. That is what the guard's
# BUDGET_SLACK absorbs, and why this number is expected to move down over time
# and to be argued over when it moves up.
