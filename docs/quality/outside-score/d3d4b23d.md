## Divergence

Added by the rubric's author after the assessor finished, per Independence
rule 2. The nearest `quantick-score` result is the campaign candidate in PR
#449: 96/100 at `c29ce130`, whose tree differs from `d3d4b23d` by one test
rename (#454).

| Theme | `quantick-score` v1.0 | `outside-score` v1.0 | Gap |
| --- | ---: | ---: | ---: |
| Overall | 9.6 | 6.5 | 3.1 |
| Code structure: sustainable engineering vs architecture and engineering | 9.4 | 6.3 and 7.6 | 3.1 and 1.8 |
| Agents: agentic development vs agent change cost | 10.0 | 4.0 | 6.0 |
| AI-operable product | 9.6 | not graded | n/a |

The overall gap exceeds 1.0, so it is a finding. The agent rows measure
different things: `quantick-score` grades the workflow that turns an objective
into a merged PR, `outside-score` grades what one change costs to read and
build. Both can be right. The code-structure rows cannot. At the campaign
baseline `e8eb23e5`, `quantick-score` gave SE1, SE2 and SE3 five points each,
and this tree contradicts all three:

- **SE1** asks for boundaries proven by a second consumer; `orderflow` and
  `trading` have one each (A1).
- **SE2** asks that ratchets prevent renewed concentration; its ratchets bound
  file lines, while 38 functions exceed 200 lines and `QuantickApp` spans 20
  files (E1, A3).
- **SE3** asks that the next feed or bar type dock without editing unrelated
  variants; `ProviderKind` and `BarSpec` are central enums, and the last bar
  type touched 75 files (A6).

`quantick-score` misreads the code here: those three criteria need a measured
condition on function size, type spread and the files a new variant touches.

The author also drafted a score before reading this report, from the same
rows: 6.8, with A6 at 4 and E5 at 5. The assessor's cited evidence (central
enums; no clippy or full test suite on Windows) supports the lower scores, so
this report keeps them. The spread between the two readings is 0.3.
