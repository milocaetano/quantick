# Native market title strip

The existing market arrangement occupies a 52-logical-point first client row in one undecorated native window. The existing 28-logical-point menu row remains below it. This stage replaces OS decoration; it does not claim a net row-height saving before the separate menu consolidation. Market IDs, feeds, background work, picker and last-market close policy retain their existing owners.

The bounded strip keeps the selected market visible. Its all-markets menu reaches overflow markets, and the plus button remains beside the strip. Tab controls use stable market IDs. Free space between markets and window controls is the native drag target; widgets do not initiate dragging. Double-clicking free space maximizes or restores. Native minimize, maximize/restore and close controls use the ordinary viewport commands, including the existing shutdown path.

Window movement, edge resizing and Windows snapping remain native OS gestures. The cockpit layout grant also reaches bounded physical desktop placement through `layout.window.placement.set`, with negative coordinates for secondary monitors. `layout.window.state.set` requests normal, maximized or minimized presentation for a named window, defaulting to the focused live market window. Both require idempotency keys and report accepted requests separately from OS-fed geometry and state in `workspace.windows`. The scene continues to report the painted viewport state. These requests run outside control replay. `layout.window.close` preserves every tab in a surviving window and refuses the final window; `app.exit` retains its authority exclusion and closed is not a valid state request.

In a normal window, the outer four logical points accept native resizing in all eight edge and corner directions. Corner targets extend twelve logical points along each adjacent edge without covering widget interiors. These targets show resize cursors and hand the primary-button gesture to the OS through egui's `BeginResize` command. Maximized, minimized and fullscreen windows do not offer these resize targets.

Market tabs transfer atomically through the headless workspace model; every native window borrows the same retained runtime. On Windows, pointer drops use the exposed same-process native window under the physical pointer, independently of pointer capture or focus. Other platforms preserve same-window reorder and outside-strip detach, but cancel ambiguous drops over sibling strips until a native z-order resolver is available. `workspace.windows.native_drop_targeting` reports the available policy. Insertion feedback uses the full painted chip, while label-only dragging and close-button exclusions remain distinct.
