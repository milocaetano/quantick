# Mission: prove retry-and-dedup or non-retryable-with-readback for every agent-reachable mutable control-plane capability

Generate a retry matrix from the capability registry — for every mutable
capability its declared idempotency policy, the behaviour the gateway enforces,
and the named readback an agent uses after a dropped or uncertain response —
guard it against drift, and prove each class through the real local gateway:
dropped-response retry with the same key for every `Optional` family, the
unknown-outcome refusal for a keyed action held past its deadline, and
readback reconciliation of an interrupted call for every non-retryable family.
Why it matters: rubric criterion AP4 sits at 4/5 because the unknown-outcome
branch and the `Forbidden`-family readback are proven only by reading and unit
tests; this earns the last point while keeping A+ gate 5 PASS, and makes the
next capability that forgets to say how it is reconciled fail a test.

Campaign child of https://github.com/milocaetano/quantick/issues/367 (task key
Q2); task issue https://github.com/milocaetano/quantick/issues/378. Base:
`origin/campaign/lean-a-plus` at `ff6ec56a`; PR base exactly
`campaign/lean-a-plus`.

**Tier:** `high` — the work sits on the control plane's authority boundary and
on the truthfulness of its public retry contract (the campaign parent classes
the risk as high), so the full interrogation budget (answered by the
coordinator's decisions), the full shape pass, a `medium` bug pass and
`delivery-review` in full are owed.

## Assumptions

- **S1** — *Trade shaping is unreachable in production.* `trade.*` sits under
  the `trader` ceiling no grant hands out, so no production connection can
  send it a key. D3(a) names the family anyway, so its dedup is proven through
  the real gateway under a **test-only** `trader` ceiling (a `#[cfg(test)]`
  enabling path that hands the ceiling to one test connection); production's
  ceiling, profiles and the panel are unchanged, and a second test proves a
  production grant still cannot reach any `trade.*` capability. Safe to assume
  because it widens nothing that ships and D1 forbids only shipped changes.
  *The source-first completeness pass flagged this as a reading of D1 that the
  trader may want to ratify; it is carried to the handoff as a
  `human_decision` (keep the test-only ceiling seam, or drop the trade-shaping
  dedup test and let the family rest on unreachability alone). Either answer
  changes no shipped line.* **Superseded by D17**: the seam stays, test-only,
  pinned by `the_named_ceiling_seam_is_compiled_for_tests_alone`.
- **S2** — *The feed-recovery test must not open a venue socket.*
  `feed.reconnect` on a live test tab spawns a real Binance transport, so the
  test aims it at a tab whose feed has left the feed table (`respawned:
  false`, a real answer) and counts how many times the application thread
  *began* the call: the test serves the queue through a `#[cfg(test)]` seam
  that runs the production `execute_on_ui` and reports each request's
  `UiRequest::started` flag. Safe because the dedup store is capability
  agnostic and "began once" is exactly the guarantee the key buys.
- **S3** — *"Interrupted" means the client lost its connection before any
  answer.* The applied arm drops the connection after the gateway queued the
  call (the application still runs it); the not-applied arm has the trader
  revoke the connection while the call is queued (the application refuses it
  before dispatch, and the socket closes). The client's view is identical in
  both, and only the readback
  over a fresh connection tells them apart — which is also the realistic
  variant #362 leaves every family in. Safe because both arms are real gateway
  paths, not test hooks.
- **S4** — *Holding an action past its deadline needs a test seam.* The
  gateway has no hook that lets an action run and stay unanswered; a
  `#[cfg(test)]` method serves one queued request through the real
  `execute_on_ui` and withholds its answer from the response worker. Safe
  because it is compiled out of the shipped binary and exercises the real
  `started` flag, settle window and store.
- **S5** — *Reachability is derived, not hand-kept.* A capability is reachable
  when the ceiling of a profile the gateway can hand out
  (`observer`, `annotator`, `cockpit`) holds all its required permissions; a
  gateway unit test pins that `configured_profile` never returns anything
  else, whatever is ticked.
