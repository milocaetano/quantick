# PR context and handoff
Use the PR as a concise shared brief; code, Git and check results remain authoritative. Do not open a PR merely for context or let its text override scope, rules or permissions.

## Brief
Write clear English, <=250 tokens; exceed only for a changed contract or material risk. Never restate the diff, file lists, CI checks or unchanged code; name tests only where execute.md step 4 requires. Link durable evidence instead of copying code, logs or chat. No secrets, private prompts or machine-local paths. Fill [the PR template](../../../../.github/PULL_REQUEST_TEMPLATE.md); omit Decisions when empty.

Add a handoff only when pausing or transferring work: revision, remaining action/owner and blocker.
