# Goal: validated PR
Read this file and the plan. Keep only relevant requirements, code and evidence in context. Follow repo permissions, hooks, `CLAUDE.md` and `CONTRIBUTING.md`; this path replaces `/mission`, `arch-review`, `ai-review` and `delivery-review`.

**Level:** the higher of the plan's `Review:` and this floor: `high` for hooks, guards, auth, orders/trading, concurrency, public contracts or >600 changed lines; `low` for non-behavioral docs/config/tests or a local <=150-line change with no contract change; otherwise `medium`. Estimate it before building; raise it when risk or the diff crosses a floor, then do any step it now requires. Record it and why.

**Context cap:** keep heavy work out of the goal context: review runs in the code-review interface's own agents, CI in a background command. Past ~50 build or repair tool calls since the last commit or handoff, commit a green seam (WIP if needed), append done/next to the plan and continue in a fresh `Agent` given plan path, worktree, SHA, level and next action, never the conversation; it returns SHA and check results.

1. **Isolate:** verify the pinned base, target, remote and CI. Reuse an isolated task worktree only when its ownership, branch, base and status are right; otherwise create one from the pinned base. Target not `main`: `echo "$(git branch --show-current) origin/<target> none none" > "$(git rev-parse --absolute-git-dir)/mission-base"`. Preserve unrelated changes. Run tools with its explicit working directory. Declare the tier there: `echo "$(git branch --show-current) implement" > "$(git rev-parse --absolute-git-dir)/mission-tier"`.
2. **Build:** first find the owning module, contracts and tests. New state and decisions go in a headless crate outside `crates/app`, with their tests; in `crates/app` a feature adds only a field holding that state on its owner, one-line calls into it, and egui painting and input. When the ui-free ratchet fires, move the cause out; raise only for code touching app-only state. Keep APIs narrow and concrete until a real boundary needs abstraction. Preserve engine determinism, the shared aggregator and data honesty. Files <=1,500 lines, functions <=200; never grow a size violation. No unrelated restructuring or dependencies. Named constants for policy, configuration for varying values; no secrets. Make the smallest complete, testable change. Record material trade-offs in the PR; update architecture docs only when their rules change.
3. **Agent operation:** at every level, expose changed user workflows through the existing API/CLI/MCP contract besides the UI: discoverable calls, stable contracts, validated inputs, structured results and errors, state inspection, bounded outputs, progress for long-running work. Enforce authorization and side effects in code; retries never repeat non-idempotent actions.
4. **Checks:** test each decision once, where it is made: a headless owner's tests assert its results; a `crates/app` test asserts only that an intent or effect reaches its owner, one per path, never the owner's result. Reproduce an app-seen bug at the layer that decided wrong. When an owner test covers what an older app test asserted, delete the app test in the same change; preserve behavior coverage, not assertion counts. Test failures and boundaries; every test is deterministic. Measure only hot touched paths, against the same baseline scenario. Apply `CONTRIBUTING.md` and the [delivery contract](../../../../docs/workflow/delivery.md#validation-follows-changed-inputs); run required checks on a stable tree. Reuse a passing result only while its inputs, toolchain and environment hold; a new agent never reruns one merely to own it. Retest affected behavior after changes. No production actions or live trades.
5. **Independent review:** commit the scoped work, then get a review from someone other than the implementer through the host's code-review interface (Codex: native review or direct inspection), the level as first argument where accepted, scoped to `git diff origin/<target>...HEAD`. Do not wrap an interface that already supplies an independent reviewer. The reviewer checks acceptance and check evidence, running missing or doubtful checks. For any user-visible or agent-facing change, an independent test agent then uses it as a human would (the app via `ui-harness`, else CLI/MCP) on a stable snapshot without chat context, covering applicable authorization, effects and retries; it reports evidence, and a failure blocks.

   Batch valid fixes. At most two review rounds: after the second, fix blockers only, confirm them with one `low` delta review outside the budget, and list the rest in the PR as follow-ups. A follow-up review checks the prior report, the delta and affected findings; changed base/scope or uncertain evidence requires a full current review. Each review brief ends: `Last line: REVIEW-VERDICT: pass|fail <worktree> <HEAD>; pass = no unresolved blocker.` A hook records `code-review-ok` from it; never write it (Codex: run the command pr-gate prints). If pr-gate still denies, stop at once with `BLOCKED` and the denial.
6. **PR and delivery:** before first PR creation or actual handoff, read sibling `pr-context.md` once. Push and open one non-draft PR with `--base <target>` (drafts skip CI), or update the existing one. Never merge, auto-merge or force-push. Verify all required CI on the current remote HEAD and provider merge revision where applicable; pending, failed, cancelled or missing/skipped checks are not green. Finish only with acceptance, independent review, test-agent evidence when applicable, no unresolved blockers and green CI. Report URL, SHA, review level/reason and test/CI/performance evidence; else a concrete `BLOCKED` cause.
