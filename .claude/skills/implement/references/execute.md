# Goal: validated PR
Read this file and the plan. Keep only relevant requirements, code and evidence in context. Follow repo permissions, hooks, `CLAUDE.md` and `CONTRIBUTING.md`; this path replaces `/mission`, `arch-review`, `ai-review` and `delivery-review`. Write task artifacts in English, preserving required product text. Use it only for a PR targeting `main`; campaign work follows its existing workflow.

**Level:** the higher of the plan's `Review:` and this floor: `high` for hooks, guards, auth, orders/trading, concurrency, public contracts, workflow instructions that change authority or validation, or >600 changed lines; `low` for non-behavioral docs/config/tests or a local <=150-line change with no contract change; otherwise `medium`. Set it before building; reassess if risk changes; record it and why.

**Context cap:** cost is quadratic in a context's length, so no context runs the whole goal. Stop one at about 80 billed requests (~25 turns) and hand off at a commit seam: build to commit, then review, CI watch and each repair round each in a fresh `Agent` that answers in one line with its SHA. A handoff carries the plan path, SHA and next action, never the conversation.

1. **Isolate:** verify the pinned base, target, remote and CI. Reuse an isolated task worktree only when its ownership, branch, base and status are right; otherwise create one from the pinned base. Preserve unrelated changes. Run tools with its explicit working directory. Declare the tier there: `echo "$(git branch --show-current) implement" > "$(git rev-parse --absolute-git-dir)/mission-tier"`.
2. **Build:** locate the owning module, affected contracts and tests before coding. Keep behavior and state with their owner; use narrow APIs and concrete implementations until a real boundary needs abstraction. Keep domain logic independent of UI, transport and storage, with UI and agents sharing the same operations. Preserve engine determinism, the shared aggregator and data honesty. Keep new or compliant code/test files <=1,500 physical lines and functions <=200; do not grow existing violations or weaken stricter repository limits. Add no unrelated restructuring or dependencies. Use named constants for policy and configuration for values that vary; never embed secrets. Make the smallest complete, independently testable change. Record material design trade-offs in the PR and update durable architectural documentation only when its rules change.
3. **Agent operation (`medium`/`high`, changed user workflow only):** expose it through the existing API/CLI/MCP contract as well as the UI, with discoverable calls, validated inputs, structured results and errors, and bounded outputs. Enforce authorization and side effects in code; make retries safe without repeating non-idempotent actions.
4. **Checks:** add deterministic tests for relevant behavior, failure and boundaries. Measure performance only when a touched path runs per frame, per trade or per bar, against the same baseline scenario. Apply `CONTRIBUTING.md` and the [delivery contract](../../../../docs/workflow/delivery.md#validation-follows-changed-inputs); run required checks on a stable tree. Reuse successful results only while tested inputs, toolchain and environment still apply. A new agent does not rerun a passing suite merely to become its owner. Retest affected behavior after changes. No production actions or live trades.
5. **Independent review:** commit the scoped work, then obtain a review from someone other than the implementer through the host's existing code-review interface (Codex: native review or direct inspection), passing the level as its first argument where accepted. Do not wrap an interface that already supplies an independent reviewer. The reviewer checks acceptance and check evidence, running missing or doubtful checks. At `medium`/`high` with changed agent-facing behavior, an independent agent also exercises the workflow from the task and published contracts on a stable snapshot, without hidden chat context.

   Batch valid fixes. A follow-up review checks the prior report, the delta and affected findings; changed base/scope or uncertain evidence requires a full current review. After all changes are committed, verified and reviewed, record from the worktree: `git diff origin/main...HEAD | git hash-object --stdin > "$(git rev-parse --absolute-git-dir)/code-review-ok"`. Never restamp an unreviewed diff.
6. **PR and delivery:** before first PR creation or actual handoff, read sibling `pr-context.md` once. Push and open one PR against `main`, or update the existing one. Keep a concise shared brief without a parallel status log. Never merge, auto-merge or force-push. Verify all required CI on the current remote HEAD and provider merge revision where applicable; pending, failed, cancelled or unexpectedly missing/skipped checks are not green. Finish only with acceptance, independent review and agent-workflow proof when applicable, no unresolved blockers and green CI. Leave the PR open. Report URL, SHA, review level/reason and test/CI/performance evidence; report a concrete `BLOCKED` cause if any required capability or proof is missing.
