# Goal: synchronize main 8f59a25c into campaign/lean-a-plus

Bring `origin/main` at `8f59a25c` (#462 native drawing clipboard, #461 volume
profile precise hit) into `campaign/lean-a-plus` through one reviewed merge
commit, preserving every behaviour both sides added and every campaign
invariant, so the campaign keeps building on the trunk the trader uses and its
next consolidated PR does not inherit a stale base (integration contract
step 6).

**Tier:** high — the coordinator assigned it: the merge lands main's drawing
input and picking code on top of phase 2 (the paper account in
`crates/paper`, the control host in `crates/control-host`, the UI-free
ratchet), where a wrong composition silently drops behaviour or breaks a
guard.

Campaign synchronization X4 of #367. Base: `campaign/lean-a-plus` at
`db719a44`. Source: `origin/main` at `8f59a25c`. Template: X3, PR #445.

## Assumptions

- **S1** — #462 widens the drawing copy/paste trigger from the Ctrl+C/Ctrl+V
  keys to egui's `Event::Copy`/`Event::Paste`, which egui-winit also emits on
  Windows for Ctrl+Insert and Shift+Insert (`is_copy_command`,
  `is_paste_command`). That is a new keyboard entry point to an existing
  behaviour, so the existing `drawing.duplicate` UI-matrix row is updated to
  name it rather than a new row added: the behaviour, its exclusion
  (`pending_capability`, issue 401) and its capability mapping are
  unchanged. Safe: the row text is prose regenerated by
  `--dump-ui-behaviour-matrix`, and the edit stays inside the UI-free
  ceiling (same line count).
- **S2** — #461 adds no capability and no gesture of its own: it narrows
  which pixels pick a fixed-range profile and which handles a locked or
  unselected profile offers. The capability inventory and retry matrix
  therefore need no row; the dump commands are rerun to prove it.
- **S3** — The bridge Python checks are not run: neither PR changes a file
  under `bridge/` or `tools/`.
