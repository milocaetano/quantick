## Summary

PR 5a of `docs/mcp-control-plane-development-plan.md`: events, cursor and the pointing channel — the plan's reason for existing (§6.5, scenario G). Stacked on PR 4 (#222, `feat/mcp-observer`), itself on #221 and #213. Merge in order; GitHub retargets each PR when its base lands.

- **Event journal** (`crates/app/src/control/journal.rs`): a bounded ring of semantic events owned by the application thread (entries and bytes, oversized payloads summarised), publishing its position through two atomics and one non-blocking send — no lock on the render path.
- **`events.read` / `events.wait`** (`events.rs`, `contract.rs`, `gateway.rs`): a cursor read that pages the journal through the UI queue, and a wait that parks on the gateway side — one global and one per-connection parked slot plus its request ID, never a UI request slot — until the journal moves or its timeout elapses; a waiter-manager thread per gateway run wakes the parked waiters, and releases a closed connection's waits at its next pass. A first read names `oldest` or `latest`; an expired cursor reports `dropped_before` (also when the gap was seen while the wait parked); `timed_out` is false once events landed; a duplicate request ID is refused while the wait is parked; overflow is `control.backpressure` (`CONTROL_MAX_PARKED_WAITERS`, `CONTROL_MAX_PARKED_WAITERS_PER_CONNECTION`). `observe.events` joins the safe default grant.
- **Frame emitter** (`gateway.rs`): while access is enabled, tab activation/open/close, focus, selection, feed market and connection, and replay state changes are journaled — the baseline is compared in place (integers, string compares, a zero-allocation `SelectionIdentity`) and an allocation happens only on a change, when the event is built; nothing while disabled.
- **Action registry port and the human mark** (`actions.rs`): `ActionRegistry` (descriptor + handler + compiled schemas) and `attention.mark.create` — effect `annotate`, permissions `annotate` + `annotate.attention`, declared beside the `annotator` profile so an observer connection is refused before dispatch, and discoverable through `describe`. The Ctrl+M hotkey, the `QUANTICK_CONTROL_MARK` hook, tests and a replayed trace entry all arrive at the same handler through `QuantickApp::control_action`. The hotkey resolves the pointer and supplies the target, so the input alone determines the mark; the result says who resolved it (`target_source: pointer | supplied | replayed`) and carries no wall-clock time (the journal event does), so the trace's result digest depends on what was marked and on its place in the journal, never on the clock.
- **Control trace** (`trace.rs`): the durable sidecar of contract §11 — `<session>.control-trace.jsonl` beside a recording, intent line before the action runs and result line after; a mark taken during a replay is re-injected at the same logical replay time on the next run of that recording, attributed to automation and not recorded again; the trace is loaded once per recording and walked by replay time (two tabs on the same file share one walk), so a tab switch neither repeats nor skips an injection; a restart or seek — counted by the replay worker, with where it landed — replays the same actions on the rerun, including the ones this run recorded, exactly as a fresh process would; entries replay at their recorded capability version and a replayed mark without its recorded target is refused rather than resolved against the rerun's pointer; a result pairs with the latest unmatched intent of its sequence and sequences continue from the sidecar's highest; an unfinished intent is logged as fixture-ineligible. `ReplayStatus::elapsed_ms` is the trace's time axis.
- **MCP**: `quantick_read_events` and `quantick_wait_for_change` over the committed schemas; the adapter extends its read patience by the wait's own timeout.
- Schemas: `observer-events-read-input-v1`, `observer-events-wait-input-v1`, `observer-event-page-v1`, `attention-mark-input-v1`, `attention-mark-result-v1`; catalog regenerated. Evidence: `docs/control-plane/pr5a-events-evidence.md`. `ui-harness` row for `QUANTICK_CONTROL_MARK`.

## Rate class and tier

Semantic changes only — never trade or frame frequency. Observe tier for reads; the mark is the first annotate-tier action and is reachable only locally in this PR (the `annotator` profile is declared, not granted by the adapter). The authority of the observer gateway is unchanged: `gateway_observer_cannot_create_a_mark_remotely_but_reads_the_registered_action`.

## Performance

- Disabled: the journal is untouched by the frame loop (`needs_frame_service()` gates `begin_frame`; the trace service is one comparison per tab per frame, nothing for a tab without a replay).
- Enabled, idle: the emitter compares its baseline in place (three integers, a `Copy` selection identity, one string compare per tab for feed and symbol, two atomics per replay link) and allocates nothing; parked waiters cost the UI thread nothing — the application thread stores two atomics and tries one bounded send per recorded event.
- A record allocates (the event and its encoded size) — at human/semantic rate, by design; the journal never sees a trade.
- A human action during a replay opens the sidecar and performs two `sync_data` (intent, result) on the UI thread — per gesture, never per frame or per trade; durable intent-before-state is what contract §11 asks for. Deferred: keeping the handle open per session and moving the result sync off the frame, once a measurement on a slow drive says it matters.

## Architecture review

Step 0: `code-review` at `high` over `feat/control-events` (its dispatched finders never reported back, so the reviewer ran the bug pass itself — stated here as the skill asks). Ten findings, four confirmed and six plausible; nine resolved on the branch head (`fix(app): the parked wait keeps its promises and the trace replays every pass`), one deferred with its reason:

1. **Confirmed** — control-trace re-injection was keyed on the active tab and reset whenever it had no replay, so switching away and back re-injected every past entry, while a restart or a backward seek never re-injected. The trace is now loaded once per replaying tab and walked by logical replay time; a playhead that moved backwards rewinds the walk (`TraceReinjection::collect_due`), every replaying tab is serviced, and `a_mark_during_replay_is_traced_and_replayed_at_the_same_logical_time` now switches tabs (one mark) and restarts (two marks, sidecar unchanged).
2. **Confirmed** — a parked-wait thread that failed to spawn leaked its parked slot and the client never heard back. The slots and the request ID are released and the client gets `control.backpressure` (retryable).
3. **Confirmed** — a parked `events.wait` was not in `in_flight_ids`, so a duplicate request ID was accepted while it parked (contract §5.2). The ID is tracked from park to answer; every terminal path of `dispatch_prepared` forgets it. `gateway_rejects_a_duplicate_request_id_while_a_wait_is_parked`.
4. **Confirmed** — `events.wait` dropped the `dropped_before` the gateway-side resolve had seen and re-read from the clamped cursor, so a client whose cursor was evicted was never told. The gap rides with the read (`EventsReadInvocation::dropped_before`) and `complete_wait_page` reports it unless the UI-side read saw a newer one.
5. Trace sequences restarted at 1 per process and a result paired with the *first* unmatched intent of its sequence, so an old unfinished intent could be "completed" by a later run's result. A result now pairs with the latest unmatched intent (`rposition`), and `next_trace_sequence` continues from the sidecar's highest sequence when the trace is loaded (the trace service runs before the hook's mark in the frame). `a_result_pairs_with_the_latest_intent_of_its_sequence`.
6. Parked waits survived a client's disconnect and were not capped per connection, so one client could hold all 16 slots for 30 s. `CONTROL_MAX_PARKED_WAITERS_PER_CONNECTION` (4; contract limits table) bounds one connection's share, and a closed connection's waits are released at the manager's next pass (`ConnectionSlots::closed`, `WakeReason::Disconnected`). The bounded-slots test now fills the per-connection cap, the global cap across connections, drops a client and sees a late wait admitted.
7. Two `sync_data` per human action during a replay on the UI thread — **deferred**: the rate is per gesture, never per frame or per trade; durable intent-before-state is the §11 requirement; the cost is declared in *Performance* above and the handle-per-session / off-frame result sync is named there as the follow-up once measured.
8. A wait woken by `TimedOut` ran its read a frame later and could carry new events while saying `timed_out: true`. `complete_wait_page` clears `timed_out` when the page is not empty; the event-page schema doc says so.
9. `semantic_key` allocated every frame while access was enabled (tab strings, the selection snapshot, the session path) against the function's own "no allocation unless something changed". The emitter now compares its baseline in place and the selection through a zero-allocation `SelectionIdentity`; the owned snapshot is built only for the event; the trace service compares the session path by reference and clones it only on load.
10. `MarkResult` stamped the wall clock into the result (so the trace's result digest could never match on a rerun) and every hotkey mark said `target_source: "supplied"`. The result no longer repeats the time the journal event carries, and `target_source` names who resolved the target: `pointer` (the human's pointer — hotkey, hook, or a caller that passed none), `supplied` (an agent passed one), `replayed` (the trace re-injected it). Schemas regenerated.

Second pass (`code-review 223 high` over the branch head after the fixes above, reviewer ran the pass itself): six plausible findings, no confirmed one; five resolved on the branch, one a wording correction:

1. Trace entries were loaded once per (tab, session) and never refreshed with the actions this run recorded, so an in-session restart and a fresh process re-injected different sets — the walk now takes each recorded action in (`TraceReinjection::record_this_pass`), not injected back on the spot, replayed on the next rerun.
2. A replayed entry without a recorded target resolved the rerun's pointer — now refused (`control.invalid_request`), so a fixture never depends on where the mouse is during the rerun.
3. Rewind detection by `elapsed < last` missed a restart whose rerun had already advanced past the last sample — the replay worker now counts restarts/seeks and publishes where they landed (`ReplayStatus::rewinds` / `rewind_target_elapsed_ms`), and the walk rewinds to that position.
4. The result digest still carries the journal `sequence`, so it depends on the mark's place in the journal — the claim is corrected (docs, `MarkResult` doc); fixture comparison (5c) decides which result fields are identity.
5. Two tabs on the same recording each walked the sidecar — one walk per recording now, keyed by session path, driven by the tab that loaded it.
6. Re-injection ignored `TraceEntry.capability_version` — `invoke_local_action` takes the version and the walk passes the recorded one; an unknown version is `control.capability_unknown`, logged with the version.

Shape: docking — the journal, the events reads, the parked wait, the action registry and the control trace each dock on an existing port or add one (`ActionRegistry` + handler signature, `ControlTrace` with `ReplayTraceFile` / `NoTrace`, `EventsReadInvocation` as one more `PreparedUiRead`, `PreparedDispatch::Parked`), and the next action or event source is one file plus one registration; performance — declared per path above, every per-frame path compares in place and allocates on change only, the journal is owned by the application thread and signals with two atomics; hardcoded — limits come from `quantick_control::limits` (two named additions documented in the contract's table), event kinds and module IDs are named constants, the hotkey is `MARK_SHORTCUT`; tests — each behaviour the plan names has one (table above), the ports have a second implementation under test (`NoTrace` beside `ReplayTraceFile`, the gateway's fake host in the control crate), and the regressions the review found each have a test that fails without the fix; standardisation — the same `control.*` vocabulary, the same schema documents, the same `PreparedUiRead` path as every other UI read; readability — module docs state each rule with its contract section; second operator — the mark is a registered action with a named ID, declared permissions and schemas, reachable from the hotkey, the hook, a test and a replayed trace through one function (`QuantickApp::control_action`), and readable back through `events.read`; remote dispatch of actions is PR 5b's (the observer profile cannot reach it, by test).
